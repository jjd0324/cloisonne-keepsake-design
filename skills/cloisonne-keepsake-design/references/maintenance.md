# 维护说明

本仓库的维护目标不是无限堆叠提示词，而是持续增加经过验证、可复用、结构清楚且不会泄露用户隐私的“风格 × 输出形式”模板。

## 新风格的准入条件

新增一种风格前，至少确认：

- 它有独立、可辨识的视觉语言，不只是已有风格换几个形容词；
- 写清参考图保留逻辑、简化规则、构图、色彩或材质、严格排除项；
- 分别说明实体纪念品与单幅艺术图如何适配，或明确某种形式不适用；
- 不复制外部作者的完整提示词、原图、签名或水印；如有研究来源，在 README 中透明说明。

## 新模板的准入条件

- 覆盖现有模板没有覆盖的参考图类型、风格、输出形式或工艺判断；
- 有一份可复制的提示词，并把参考图不变量、风格和输出结构写清楚；
- 有一张公开可用的预览图，或有充分理由暂不提供预览；
- 不含用户原图、可定位的私人信息、未经许可的人像或品牌素材；
- 通过 [质量检查表](quality-checklist.md) 的对应分支。

## 推荐节奏

- 每月：整理真实使用中重复出现的一个需求，判断应新增风格、模板还是只修正规则；
- 每次新增模板：同步更新 [模板索引](templates/README.md)、预览清单与根目录 README；
- 每次修改：运行 `python scripts/validate_skill.py`，检查模板、预览与引用没有断裂；
- 每个小版本：在根目录 [CHANGELOG.md](../../../CHANGELOG.md) 写清新增内容、修复内容、研究来源和隐私边界变化。

## 不自动做的事情

- 不把用户上传的照片自动提交到公开 GitHub；
- 不把“图片生成成功”写成“已可量产”或“已完成真实手绘原作”；
- 不为凑数量复制近似模板；
- 不因增加新风格破坏旧调用名和已有安装；
- 不在没有确定性处理需求时引入笨重脚本或视频生成管线。

## 反馈入口

仓库提供“模板建议”和“质量问题”两类 Issue 模板。新需求应说明参考图类型、目标风格、输出形式、当前失败点和是否能公开示例。
